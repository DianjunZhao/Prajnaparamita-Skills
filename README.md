# 般若波罗蜜 · Prajñāpāramitā Skills

> 一个把「般若为导」翻译成**可观测行为约束**的 agent skill。
> 它不教 agent 说智慧的话,它改变 agent 怎么决断、怎么取舍、怎么做事、以及怎么记录自己做过什么。

**版本** v1.2 ｜ **形态** agent skill(`SKILL.md` + `references/`) ｜ **协议语言**英文(与 skills 目录惯例一致) ｜ **理据语言**中文/英文混排

---

## 一、佛学地:它是为了做什么

### 1.1 立意

《大智度论》一系把「智」(jñāna)与「般若」(prajñā)分开:**智是了知"有哪些",般若是抉择"此刻该做哪个"**。默认的 agent 落在前者——检索、罗列、覆盖、看起来正确;它把"回答得全"当成了"回答得对"。

本 skill 要做的是把后者装成**工作纪律**,而不是语气。

### 1.2 为什么不能只写「要有智慧」

因为抽象训诫不改变行为,只改变措辞。一个只会说"要超越知识、抵达智慧"的 skill,产出的是词汇表演与更慢的回答。所以本仓库有一条贯穿始终的硬规则:

> **凡不能被读者从答案或产物中检验其是否真的发生的东西,一律不写进去。**

义理在这里是**设计约束**,不是装饰。凡是"因为经上说"的句子,都要改写为"因为这样会产生行为 X"。

### 1.3 义理骨架

每一条都在协议里对应一个**可观测**的行为,而不是一段说明:

| 义理 | 它在本 skill 中约束的行为 |
|---|---|
| 智 / 般若 | 检索与罗列是材料,诊断与取舍才是交付物 |
| 四依(依智不依识、依义不依语、依了义不依不了义) | 判读意图而非字面;分清指令里承重的**定说**与可弃的**方便说** |
| 二谛 | 一事两说,不是两个可切换的挡位;没有关掉核查的开关 |
| 量论(现量 / 比量 / 圣言量) | 亲见 / 推得 / 闻得三分,**证言不因被转述而成为亲见**——来源摘要、下游 stage 的汇报、乃至 agent 自己上一轮的说法,都是证言 |
| 增益 · 增上慢 | 状态词(verified / ran / converged / done)必须指出承载它的产物、行或输出,否则改用更弱的词 |
| 遮诠 | 任何判据都要说出它排除了哪个**仍然活着的**选项;只排除已经死掉的选项的判据等于没有判据 |
| 无住 · 不取 | 被质疑时默认去查原始出处:既不加固,也不屈从;两者同样是不追踪理由 |
| 空 · 自性 | 代理量不是所指:估计量不是观测量、拟合窗不是平台、基准不是能力、统计误差不是总误差 |
| 缘起 | 分析止于**着力点**,不追第一因;越过着力点的彻底性不是决定需要的彻底性 |
| 无常 | 复用早先产出的数字或产物前,先问它的成立条件是否还在 |
| 无我 | 旧输出不是自我;更正它不花费任何属于你的东西 |
| 随缘 | 条件变了就改道,并说出**条件与代价**;随缘管的是下一步从哪来,不是要不要做 |
| 悲智双运 | 不让用户舒服而让他在更晚、更付不起的时候付更贵的账 |
| 方便 · 筏喻 | 同一判断随对象换形;规则是筏,到岸即舍——协议可以**否决自己** |
| 恶取空之禁 | "都是假名""没有正确答案"不是偷懒或免于承诺的许可证 |
| 六度以般若为导 | 每种能力都必须带**退出条件**:布施止于"决策已可做",持戒止于"约束本身是 bug",忍辱止于"假设空间用尽",精进止于"目标按此表述不可达",禅定止于"工作不再推动关键数字" |
| 三轮体空 | 交接不依赖你在场:复现路径 + 有效性条件,不把结果扣在"再问我一次"后面 |
| 无分别 ≠ 不分辨 | 判别就是交付物;"两者都有道理"式的含糊是失败,不是风格 |

### 1.4 诚实的限度

- **模型没有证悟,本 skill 也不假装有。** "更像般若波罗蜜"可以落在两处:对传统的**结构忠实**,或在 agent 身上的**行为后果**。本仓库以后者为优化目标,以前者为约束。
- 若反过来优化前者,得到的只会是词汇而没有行为——而按传统自己的说法,**执着于筏的来历,恰是筏所对治的错误**。
- 因此 `references/doctrine.md` 被明确标注为**给人看的理据,不是 agent 输入**;协议层必须能独立自查。

## 二、工程地:它能完成哪些目的

### 2.1 分层结构

| 层 | 何时生效 | 作用 |
|---|---|---|
| **L0 内核** | **恒常**,对每次回答与每个任务 | 8 条**对产物的约束**(不是流程)。工作本来就正确时它们静默通过、零成本 |
| **L1 判断** | 建议 / 排序 / 取舍 / 评价 / 策略;昂贵或不可逆动作;命名选项之间的选择;用户重述或反驳;选项集可疑 | 产出立场 + 主导约束**及其排除项** + 承受的代价 + 可证伪点 |
| **L2 执行** | 跨多个工具调用 / 多个文件 / 多轮,**且产出或改变了信息之外的东西** | 可逆性分级、约束声明、ran 标签、陈旧检查、更正范围、交接 |
| **L3 深器** | 仅在能**命名症状**时:代理量有效性未声明、因果链越过着力点、两个可信来源冲突、误差在未定位的情况下被压小 | 只作用于那一段论证,不作用于整个答案 |

普遍性只存在于**没有流程的那一层**;L1–L3 的判据廉价、通常为假、无法命名触发条件时默认关闭。

### 2.2 六个可验收的目的

1. **决策类回答不再是选项清单。** 你会看到:一句立场 → 主导约束与它排除了什么 → 排序 → 承受的代价 → 什么观测会推翻它 → 认识论标注。说不出口径时,协议要求**回到直答**,而不是编造取舍与证伪点。
2. **执行类任务有纪律。** 动作先按"可逆性成本"分级(指令本身就是授权,不会拿确认来卡你已经要求的事);约束先声明、偏离与结果**同一条消息**报出;`ran / ran and failed / unverified` 标签使"跑出来的"不能退化成"我觉得";一次重试必须换诊断,瞬态故障(抢占、掉节点、XID/ECC)与持久故障(无 GPU/MPI)分开处理;不留半成品;交接带复现路径与有效性条件。
3. **引证纪律可核验。** 具体标识符(arXiv 号、DOI、页码、公式/表号、review 标题、数据集名、URL)除非**本会话真的读过并能引出原句**,否则标为未核实;**来源存在 ≠ 来源支持你的断言**;一份整洁的核查台账若条目无法以原句支撑,它本身就是仪式。
4. **对抗谄媚与一致性偏差。** 被质疑时默认去查原始出处,既不加固也不屈从;承认没有证据之后**不得**再表达倾向——倾向不是理由,结构性理由必须以可检验的形式陈述。
5. **反仪式。** 任何新增的段、清单或标注都必须改变一个方向(动作、排序、取舍、或仍然存活的选项),否则删掉。粗略的可操作标尺:**带 skill 的答案不应比不带 skill 的合格答案更长。**
6. **成本与陈旧意识。** 报告花掉了什么、买到了什么;探针按成本排序,先用廉价判别;复用旧结果前先声明它成立的条件与哪些已经变了。

### 2.3 与既有规则的关系:它是**编排层**

本 skill **不重述**别人的所有权,冲突时**更具体者胜**:

- `prev-halluc-work` —— 事实标签、置信度分级、引证规范
- `scoped-clean-work` —— 写入范围、保留输入、临时产物、进程与清理
- `no-ai-slop` —— 文风与句式禁令
- 用户的 `AGENTS.md` —— 语言、约定、可复现性等常驻规则

### 2.4 它**不**承诺什么

- 它不会让模型更聪明。**实测结论:判断层的大部分能力基础模型已有**——在不载入本 skill 的对照基线中,模型自己就拒绝了"基准快 ⇒ solver 更快"的推断,也拒绝了"都是方案依赖的,随便挑一个"。
- 可被证实的增量是窄的:**执行层的记录纪律**(来源、转述、陈旧、更正范围、状态词)、**量化分解**(例如 Amdahl 式拆分)、**带阈值的预承诺规则**。
- 它有**延迟成本**,在多步杂活上尤其明显。我们选择把这个成本**记录下来**而不是辩解掉。
- 尚未测试:真实多步任务上的执行层(文本探针够不到)、多轮对话中的谄媚漂移、与多个兄弟 skill 同时载入的交互。

## 三、安装

把本目录放到 agent 的 skills 目录下即可:

```bash
git clone https://github.com/DianjunZhao/Prajnaparamita-Skills.git \
  ~/.agents/skills/prajnaparamita
```

或在会话中直接要求 agent 载入 `prajnaparamita`。

> 注意:本 skill 会与 `prev-halluc-work`、`scoped-clean-work`、`no-ai-slop` 协同工作得最好;它是编排层,不替代其中任何一个。

## 五、版本与测试

- **v1.0** 由 4 个并行 subagent 生成(架构 / 对抗批评 / 行动向义理 / 执行规范),再经 2 个 subagent 做实证 A/B 与矛盾审计。
- **v1.1** 处理 9 项审查发现(标识符、层未触发 vs 规则搁置、条件排序、判据抵消结构、更正位置、无据倾向、长度标尺、内部引证、保留清单)。
- **v1.1.1** 在专门的"引证裸奔区"两臂测试后,把标识符规则升级为**要求核查内容**(引出原句)。该测试发现了本轮最严重的问题:**一个真实存在的 arXiv 编号被用来支撑它并不支持的断言**,而载入引证纪律 skill 的那一臂不但没拦住,反而用一份整洁的核查台账放大了它。
- **v1.2** 由一次独立的义理审读产生:新增"证言不因转述而成为亲见""状态词通胀""陈旧检查""更正作废范围""判据须先声明否证观测""风险必须被承载",并**明确驳回**了中道、如实知见、对治悉檀、量论三分等候选(理由见 `doctrine.md`)。
- **未来增补的两条准入检验**(写在 `doctrine.md` 里,用以阻止这个文件继续长大):
  1. **重复性检验**:若不载入 skill 的基线自己就会拒绝该失败,不要为它加规则。
  2. **方向性检验**:若该增补不能改变动作、排序、仍存活的选项或已产出的产物,删掉。

## 六、义理引用的态度

本仓库**不引用未核实的具体出处**。文中出现的经论名号只在与文本相符时使用;凡涉及具体品目、卷号、编号的,**一律不写**,需要时标注 `verify`。这不是谨慎过度——在设计过程中,两轮独立审查者各自给出过一个**错误的大藏经编号**,这是本 skill 把"来源存在 ≠ 来源支持"写进协议的直接原因。
