# 般若波罗蜜 · Prajñāpāramitā Skills

> 一个把「般若为导」编译成**可被检验的行为约束**的 agent skill。
> 它不教 agent 说智慧的话;它改变 agent 怎么决断、怎么取舍、怎么做事、怎么记录自己做过什么。

**版本** v1.5 ｜ **形态** `SKILL.md` + `references/`(7 个文档文件,846 行) ｜ **协议语言**英文 ｜ **许可证** MIT

**一句话主张**:本仓库把义理当**设计约束**用,而不是当修辞。凡不能被读者从答案或产物中检验其是否真的发生的东西,一律不写进协议。

## 一、佛学地:为什么是「般若波罗蜜」

### 1.1 般若不是「更聪明」

智(jñāna)是了知"有哪些";般若(prajñā)是抉择"此刻该依什么"。默认的 agent 落在前者——检索、罗列、覆盖、看起来正确;它把"回答得全"当成了"回答得对"。

这里有个陷阱:任何直接写成"要有智慧"的指令都只改变语气。所以本仓库的第一条设计原则是**可检验性**——每条规则都必须能被读者从产物中看出是否发生。

### 1.2 核心动作是减法,不是加法

般若波罗蜜一系的中心动作**不是知道更多,而是撤回实在化**(svabhāva,自性):空不是"什么都没有",而是"没有任何东西独立于条件而成立"。落到工程上,它有一个锋利且可检验的形式:

> **一个判据若说不出它排除了什么,它就没有排除任何东西。**

这是本仓库在全部检验之后**唯一存活的判断层规则**。原因不是它最漂亮,而是它抓住了默认行为的真正缺口:无辅助的答案会跳过"这一步排除了哪个仍然活着的选项"。

同一次撤回的其他工程形式:

| 义理 | 工程形式 |
|---|---|
| **空 / 自性** | 代理量不是所指:估计量不是观测量、拟合窗不是平台、基准不是能力、统计误差不是总误差 |
| **无住 / 不取** | 被质疑时默认去查:既不加固也不屈从;且**核查台账本身也是断言**,不能被引句支撑的条目即为仪式 |
| **缘起** | 分析止于着力点,不追第一因——越过着力点的彻底性不是决定需要的彻底性 |
| **无常** | 复用早先产出的数字前,先问它成立的条件是否还在 |
| **无我** | 旧输出不是自我;更正它不花费任何属于你的东西 |
| **三轮体空** | 交接不依赖你在场:复现路径 + 有效性条件 |
| **悲智双运** | 不让用户舒服,而让他在更晚、更付不起的时候付更贵的账 |
| **五度如盲,般若如导** | 每种能力都必须带**退出条件**:布施止于"决策已可做",精进止于"目标按此表述不可达",禅定止于"工作不再推动关键数字" |

### 1.3 二谛:不是两个挡位

二谛不是两个世界。约定层面,方法、误差棒、决定都在运作;究竟层面,它们都没有自性。**究竟不是与约定并列的另一个事实,而是看约定而不实在化它。**

这在工程上非常具体:v1.0 曾有一张"知识模式 / 智慧模式"对照表,并在 v1.3 **被删除**——因为"模式"意味着挡位,而挡位会邀请 agent 在自觉深刻时把事实层关掉;它同时是全文件最大的仪式诱因。删掉它不是削弱义理,而是在执行义理。

### 1.4 筏喻:本仓库对自己做的事

> 法尚应舍,何况非法。

规则是渡河的筏,不是要收藏的东西。这句话在这里不是隐喻,而是一条**被实际执行的工程流程**——两条准入检验:

1. **重复性检验**:若不载入 skill 的基线自己就会拒绝该失败,不要为它加规则。
2. **方向性检验**:若该增补不能改变动作、排序、仍存活的选项或已产出的产物,删掉。

把这两条**回过来用在已有规则上**,结果是内核从 8 条删到 **2 条**,判断层共有 **10 条**规则被不载入 skill 的基线逐一追平。这不是失败,而是这个传统本来的主张:**筏不是用来收藏的**。

同时,一个要求"每条规则都要过闸"的 skill 必须公开**哪些还没有过闸**——逐条全表在 `references/doctrine.md` 的 "Evidence status of every rule"。**不完整的披露比不披露更糟。**

### 1.5 恶取空之禁

本仓库把传统对"误解空性"的警告当作**明文禁令**:"都是假名""本来就没有正确答案""都只是模型"——凡是**用来撤回严格性、或用来免于承诺的**,一律禁止。空性撤掉的是答案的独立存在,不是选择的后果。

### 1.6 借用与分界的诚实声明

- **属于传统的**:四依、二谛、四句(仅借"选项集是否穷尽"之问)、无住/不取、空与自性、缘起、无常、无我、随缘、三轮体空、悲智双运、方便与筏喻、恶取空之禁、五度如盲般若如导(论疏说法)、三慧。
- **属本仓库自己的类比**:把"无我"用到 agent 对自己旧输出的态度上;把"三轮体空"用到软件交付上;把"三慧"第三支对应到"命令执行";把代理量批判对应到具体技术量。
- **不引未核实的具体出处。** 三轮独立审查者各自给出过一个汉文大藏经编号,其中两个是错的——这是本仓库把"来源存在 ≠ 来源支持"写进协议的直接原因。

### 1.7 天花板,诚实地说

模型没有证悟,本仓库也不假装有。"更像般若波罗蜜"可以落在两处:对传统的**结构忠实**,或在 agent 身上的**行为后果**。本仓库以后者为优化目标、以前者为约束;若反过来优化前者,得到的只会是词汇而没有行为——而按传统自己的说法,**执着于筏的来历恰是筏所对治的错误**。

## 二、工程地:它到底改变什么

### 2.1 四处具体改变(前后对照)

**判据**

- 前:「拟合收敛了,可以写进论文。」
- 后:「收敛判据是 X(它排除的是"窗口未扫"这个仍然活着的选项);否证观测是 Y,已在昂贵步骤**之前**声明;我没读到你的数据,因此数值位置标为未核实。」

**来源**

- 前:「文献里是这么说的。」
- 后:「本会话读到的是这一句(引出原句);编号未经核实;有一个是凭记忆的,只作**查找线索**,不作支撑。」

**更正**

- 前:改掉眼前那句话。
- 后:点名这次更正**作废了哪些下游产物**,并逐条修掉或标注未修。

**收尾**

- 前:「做完了。」
- 后:代价(工具调用 / 算力 / 磁盘)、买到了什么、以及**点了名但没解决**的问题。

### 2.2 何时启用 / 何时关掉

**启用**:建议、推荐、决策、取舍、排序、优先级、评价、推导与估算、有争议的事实主张、多步任务、诊断与调试、代码与文件改动、昂贵或不可逆动作、命名选项之间的选择、含糊指令。

**关掉**:纯查证、定义、检索、格式转换、单位换算,以及**单步、单文件、单轮**的指令。跨多工具 / 多文件 / 多轮**且产出或改变了信息之外的东西**时才启 L2;查三次也还是查。

### 2.3 分层与开销

| 层 | 何时 | 作用 |
|---|---|---|
| **L0 内核** | **恒常**(2 条) | 对**产物**的约束,不是流程;工作本来就正确时静默通过、零成本 |
| **L1 判断** | 建议 / 排序 / 取舍 / 评价 / 策略;昂贵或不可逆动作;命名选项;用户重述或反驳;选项集可疑 | 立场 + 主导约束**及其排除项** + 承受的代价 + 可证伪点 |
| **L2 执行** | 跨多工具 / 多文件 / 多轮,且产出或改变信息之外的东西 | 可逆性分级、约束声明、`ran` 标签、陈旧检查、更正作废范围、交接 |
| **L3 深器** | 仅在能**命名症状**时(代理量有效性未声明、因果链越过着力点、两个可信来源冲突、误差在未定位时被压小) | 只作用于那一段论证,不作用于整个答案 |

**开销**:内核在答案本来就正确时零成本;L2 的声明义务**随运行规模伸缩**(两分钟的诊断只要两三个值,不是一整张表);每步重新决策是**静默**的,只在决策改变时输出条件与代价。

### 2.4 与既有规则的关系:它是**编排层**

它**不替代**任何一个,冲突时**更具体者胜**:`prev-halluc-work`(事实标签与引证)、`scoped-clean-work`(写入范围与清理)、`no-ai-slop`(文风与句式)、`AGENTS.md`(语言、约定、可复现性)。

### 2.5 它**不**承诺什么(把实测的负面结论放在明处)

- **它不会让模型更聪明。** 实测:判断层**每一条**被探过的规则(10 条)都被不载入 skill 的基线追平;唯一存活的是"约束须说出它排除了什么"。
- **执行层在真实长任务中未能归因。** 两臂各跑一条真实三段流水线(含中途参数更正与一个不存在的参照文件);产物层面两臂都做到了约束声明、作废失效结果、识别陈旧标定、可移植交接、拒绝编造参照。该轮**测不出差异**,而且形态证据被我自己的测试支架污染。
- **有开销,但开销的归因同样不成立。** 长任务中载入 skill 的一臂墙钟约为基线的 8 倍,但额外时间花在**自愿多做复核**上,而规则的方向恰恰相反(判据先声明、止于着力点都是**限制**开销的)。
- **未测**:多轮对话中的谄媚漂移;多个 skill 同时载入的交互。
- 要真正回答"执行层是否必要",需要一次**努力量匹配、盲评、可重复**的比较。在此之前它的诚实状态是:**既未被证明多余,也未被证明必要。**

## 三、快速开始

```bash
git clone https://github.com/DianjunZhao/Prajnaparamita-Skills.git \
  ~/.agents/skills/prajnaparamita
```

然后在会话中要求 agent 载入 `prajnaparamita`。它的最佳搭档是 `prev-halluc-work`、`scoped-clean-work`、`no-ai-slop`。

**怎么确认它在你这儿真的生效**:用 `references/eval.md` 的 12 个探针,每个跑**两臂**(载入 / 不载入),只数**方向性**差异——动作变了、排序变了、便宜的探针取代了昂贵请求、拒绝了一个非穷尽的选项集。多加一个标签、复述一句用户的话、给一个没有量级的代价,都算**形式**差异,不计分;两个以内算通过。同一文件的「探针设计」一节还列出三种会让探针失效的写法:提示里禁止或要求了被测行为;**失败不够诱人**(要求编造数据这种显眼的不端,两臂都会拒绝,测的是模型训练而不是 skill);没有基线臂。

## 四、这个仓库如何对待自己的规则

这是本仓库最不寻常的一节,也是 §1.4 筏喻的工程落实:

- **内核只有 2 条**,因为另外 6 条被两道检验删掉了,而且**每条都写明了迁去了哪里**。
- `references/doctrine.md` 里有**逐条规则的证据状态表**:哪些通过了成对探针、哪些至今**没有证据**(挂账)、以及哪一条是"保留但未被证明"。
- 删除的理由、被驳回的义理候选(中道、如实知见、对治悉檀、量论三分……)与驳回理由全部留档——**没有一条是无声消失的**。
- 探针设计本身也被审查:三次"探针太钝"被写成规范,因为**没有基线臂的洞见,再漂亮也不该进协议**。
- 轨迹:v1.0 → v1.5,内核 8 → 4 → 2 条;引证规则在"引证裸奔区"两臂测试后升级为**要求核查内容**;长任务测试在案但**未能归因**。
